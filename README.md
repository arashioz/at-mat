# At Mat

مخزن یکپارچهٔ سایت فارسی ات‌مت، پنل ادمین و API. هر سه برنامه از ریشهٔ همین مخزن نصب، build و اجرا می‌شوند. راهنمای کامل سایت و تحویل دارایی‌ها در [web/README.md](web/README.md) است.

## بخش‌ها و تکنولوژی‌ها

- `web/`: سایت مصرف‌کننده با Next.js 16، React 19 و TypeScript؛ صفحات شش طعم محصول، رسپی‌ها و مجله. Three.js برای قوطی سه‌بعدی و GSAP / ScrollTrigger و Motion برای حرکت‌ها استفاده می‌شوند. طراحی فارسی و RTL است.
- `admin-web/`: پنل مدیریت با Next.js 14، React 18، TypeScript و Tailwind CSS 3؛ مدیریت مشتری، محصول و مقالات.
- `backend/`: NestJS 10، Mongoose / MongoDB 7، احراز هویت JWT و ذخیرهٔ تصاویر در MinIO با AWS SDK S3.
- `docker-compose.yml`: سرویس‌های MongoDB و MinIO همراه volume پایدار؛ برنامه‌های Node روی میزبان اجرا می‌شوند.

نسخهٔ دقیق وابستگی‌های هر بخش در `package.json` و `package-lock.json` همان بخش ثبت شده است. وابستگی‌ها با npm نصب می‌شوند؛ پوشهٔ `node_modules` تحویل داده نمی‌شود.

## راه‌اندازی محلی

پیش‌نیاز: Node.js نسخهٔ 22، npm و Docker با Compose. ابتدا بستهٔ جداگانهٔ دارایی‌ها و داده‌ها را مطابق [راهنمای فرانت](web/README.md#داراییها-و-دادههای-خارج-از-گیت) تحویل بگیرید؛ clone مخزن به‌تنهایی شامل تصاویر و فونت‌ها نیست.

از ریشهٔ مخزن:

```sh
npm run install:all
cp .env.example .env
cp backend/.env.example backend/.env
cp web/.env.example web/.env.local
cp admin-web/.env.example admin-web/.env.local
```

دستورهای `cp` فقط برای راه‌اندازی اولیه هستند؛ فایل تنظیمات موجود را بازنویسی نکنید. در `backend/.env`، `JWT_SECRET` را به مقدار تصادفی و `ADMIN_EMAIL` و `ADMIN_PASSWORD` را به اطلاعات ادمین خود تغییر دهید. در `.env` ریشه، `MINIO_ROOT_USER` و `MINIO_ROOT_PASSWORD` را تنظیم کنید و همان مقادیر را در `MINIO_ACCESS_KEY` و `MINIO_SECRET_KEY` بک‌اند قرار دهید. Compose رمز ثابت در سورس ندارد و بدون تنظیم این متغیرها اجرا نمی‌شود. همهٔ مقادیر `replace-with-...` نمونه هستند و باید عوض شوند؛ روی سرور از اطلاعات اختصاصی و دسترسی محدود استفاده کنید.

پس از بازیابی تصاویر MinIO، manifest و فونت‌ها:

```sh
npm run check:assets
npm run dev
```

`dev` ابتدا MongoDB و MinIO را اجرا می‌کند و سپس API، پنل و سایت را هم‌زمان بالا می‌آورد. در اجرای اول صبر کنید API به MongoDB متصل شود. آدرس‌های پیش‌فرض:

- سایت: <http://localhost:3002>
- ادمین: <http://localhost:3001>
- API: <http://localhost:3010/api>
- مستندات Swagger: <http://localhost:3010/docs>
- MongoDB روی میزبان: `localhost:27018`
- MinIO: <http://localhost:9000>؛ کنسول: <http://localhost:9001>

برای محتوای مقالات، بکاپ MongoDB را جداگانه بازیابی کنید. روی دیتابیس خالی می‌توانید پس از آماده‌شدن API و دارایی‌ها، در ترمینال دیگری `npm run seed:articles` را اجرا کنید؛ این دستور با ادمین تعریف‌شده در `backend/.env` وارد می‌شود، مقالات نمونه را درج و منتشر می‌کند و موارد موجود را بازنویسی نمی‌کند. اگر رمز ادمین موجود در دیتابیس قبلاً تغییر کرده است، مقدار env باید با رمز فعلی تطبیق داشته باشد.

برای بررسی اتصال کامل، در حالی که هر سه برنامه فعال هستند:

```sh
npm run check:integration
```

این بررسی API عمومی و محافظت‌شده، پراکسی ادمین، تمام صفحات طعم‌ها، رسپی‌ها و مقالات منتشرشده و پاسخ تصویری اشیای manifest از پراکسی سایت را کنترل می‌کند. نبود تصویر ارجاع‌شده در صفحات یا مقالهٔ منتشرشده خطا محسوب می‌شود. ورودی‌های قدیمی manifest که در هیچ صفحهٔ فعلی استفاده نمی‌شوند و فایلشان موجود نیست، جداگانه به‌صورت هشدار گزارش می‌شوند و باید پیش از تحویل دارایی‌ها از طریق API بررسی شوند.

## Build و اجرای نسخهٔ آماده

```sh
npm run build
npm run db:up
npm start
```

`build` هر سه برنامه را build می‌کند و `start` هر سه را هم‌زمان اجرا می‌کند. این فرایند به فایل‌های env و دارایی‌های جداگانه نیاز دارد. هنگام استفاده از `start`، نمونه‌های `dev` را متوقف کنید تا پورت‌ها اشغال نباشند. برای توقف دیتابیس‌ها `npm run db:down` را اجرا کنید؛ volumeها حذف نمی‌شوند.

## فایل‌هایی که وارد GitHub نمی‌شوند

- کل `assets/`، از جمله `image-manifest.json` و سوابق پرامپت‌های تصویر؛ این فایل‌ها با بستهٔ دارایی‌ها منتقل می‌شوند. manifest توسط API نگهداری می‌شود و نباید دستی ویرایش شود.
- تصاویر، ویدیوها، مدل‌های سه‌بعدی، فایل‌های طراحی، فایل‌های فونت در `web/src/fonts/` و پوشه‌های `Brand Assets`؛ تصاویر واقعی در MinIO می‌مانند.
- اسکرین‌شات‌ها و خروجی بررسی در `artifacts/`، آرشیوها و بکاپ‌ها.
- `node_modules/`، `.next/`، `dist/`، کش‌ها، coverage و `*.tsbuildinfo`؛ این‌ها قابل تولید مجدد هستند.
- فایل‌های `.env` و `.env.*` به‌جز `.env.example`، کلیدهای خصوصی، گواهی‌ها، توکن رجیستری در `.npmrc` و اطلاعات ورود واقعی.
- داده‌های MongoDB و MinIO، uploads، dump دیتابیس، لاگ‌ها، تنظیمات محلی IDE و فایل‌های سیستم‌عامل.

کد، محتوای متنی رسپی‌ها، seed نمونهٔ مقالات، اسکریپت‌ها، envهای نمونه و تمام `package-lock.json`ها باید در گیت بمانند. قواعد کنارگذاشتن در `.gitignore` ثبت شده‌اند. اگر فایلی از قبل tracked باشد، افزودن آن به `.gitignore` کافی نیست؛ برای manifest باید هنگام آماده‌سازی کامیت، `git rm --cached -- assets/image-manifest.json` اجرا شود. این دستور فقط رهگیری گیت را قطع می‌کند و فایل محلی را حذف نمی‌کند؛ نسخهٔ موجود در تاریخچهٔ کامیت‌های قبلی را هم پاک نمی‌کند.
