# فرانت سایت ات‌مت

`web/` سایت فارسی و راست‌به‌چپ مصرف‌کننده است و کنار `admin-web/` و `backend/` در همین مخزن نگهداری می‌شود. نصب و اجرای یکپارچه از ریشهٔ مخزن در [README اصلی](../README.md) توضیح داده شده است.

## تکنولوژی‌ها

- Next.js `16.4.5` با App Router، Server Components، صفحات پویا و Turbopack.
- React و React DOM نسخهٔ `19.3.1` و TypeScript `5.9.3`.
- Three.js `0.187.0` برای مدل و متریال قوطی و رندر WebGL.
- GSAP `3.15.0`، ScrollTrigger و `@gsap/react` نسخهٔ `2.1.2` برای حرکت‌های اسکرول و صحنهٔ محصول.
- Motion `14.9.0` برای تعامل‌ها و گذارهای رابط.
- CSS معمولی با متغیرهای طراحی در `src/styles/tokens.css` و فایل‌های CSS هر قابلیت؛ فونت محلی Peyda با `next/font/local`.
- Node.js `>=22 <23` و npm؛ نسخه‌های نصب‌شده با `package-lock.json` قفل می‌شوند.

پنل ادمین برنامهٔ جداگانهٔ Next.js 14 / React 18 / Tailwind 3 است. این دو برنامه را با package و lockfile خودشان نصب کنید و نسخه‌هایشان را با هم جایگزین نکنید.

## ساختار و مسیرها

- `src/app/`: مسیرها، layout، metadata و مدیریت خطا.
- `src/features/products/`: کامپوننت مشترک صفحات شش طعم و اطلاعات هر طعم.
- `src/features/brine/`: صحنهٔ سه‌بعدی، حرکت‌ها، نمایش ترکیبات و بخش‌های محصول.
- `src/features/recipes/`: فهرست، جست‌وجو و صفحات رسپی؛ متن رسپی‌ها در `content.json` است.
- `src/features/articles/`: فهرست و خواندن مقالات منتشرشده از API.
- `src/lib/server/`: دسترسی سمت سرور به metadata تصاویر.

مسیرهای عمومی: `/`، `/flavors/[flavor]`، `/recipes`، `/recipes/[slug]`، `/articles` و `/articles/[slug]`. طعم‌های فعلی `brine`، `sunflower`، `olive-oil`، `pepper`، `smoked` و `dill` هستند.

## اتصال به API و تصاویر

دادهٔ مقالات از `GET /api/public/articles` و `GET /api/public/articles/:slug` در NestJS گرفته می‌شود. این درخواست‌ها سمت سرور و بدون cache هستند. پنل با JWT از `/api/articles` برای ویرایش و انتشار استفاده می‌کند. کلیدهای عکس در مقاله به اشیای ثبت‌شده در manifest ارجاع می‌دهند.

متن محصولات و رسپی‌ها فعلاً در سورس است؛ endpoint عمومی محصول یا رسپی برای این صفحات وجود ندارد. تصاویر از روی metadata موجود در `../assets/image-manifest.json` پیدا می‌شوند و مرورگر آن‌ها را از `/media/...` دریافت می‌کند. Next.js این مسیر را به bucket واقعی MinIO پراکسی می‌کند تا عکس‌ها و تکسچرهای WebGL از همان مبدأ سایت دریافت شوند.

پنل ادمین هم `/api/...` را از مبدأ خودش به API پراکسی می‌کند. اطلاعات ورود به API نباید در env عمومی یا کد کلاینت قرار بگیرد.

## تنظیمات محیط

برای اجرای محلی، `web/.env.example` را به `web/.env.local` کپی کنید:

```dotenv
ATMAT_API_URL=http://127.0.0.1:3010/api
ATMAT_MEDIA_URL=http://127.0.0.1:9000/at-mat-assets
NEXT_PUBLIC_SITE_URL=http://localhost:3002
```

- `ATMAT_API_URL`: آدرس سمت سرور API، شامل `/api`. در env پنل نیز همین آدرس را تنظیم کنید.
- `ATMAT_MEDIA_URL`: آدرس سمت سرور bucket تصاویر، شامل نام bucket؛ بدون نام کاربری یا رمز در URL.
- `NEXT_PUBLIC_SITE_URL`: مبدأ عمومی سایت برای canonical، metadata و لینک مشاهدهٔ مقاله در پنل. برای انتشار، دامنهٔ واقعی سایت را در env هر دو فرانت قرار دهید.

در بک‌اند، `PORT` پیش‌فرض `3010` است. اگر پورت یا میزبان API عوض شد، env سایت و پنل را هم هماهنگ کنید. `MINIO_ENDPOINT`، `MINIO_BUCKET` و `MINIO_PUBLIC_URL` بک‌اند باید به همان فضای ذخیره‌سازی اشاره کنند. پس از تغییر متغیرهای عمومی یا مقصد rewrite، دوباره build و restart کنید. روی سرور، `127.0.0.1` به همان ماشین یا کانتینر برنامه اشاره می‌کند؛ برای سرویس‌های جدا از hostname قابل‌دسترسی استفاده کنید.

## دارایی‌ها و داده‌های خارج از گیت

قبل از dev یا build، بستهٔ جداگانهٔ دارایی‌ها را بازیابی کنید. تصاویر را در `public/` یا پوشه‌های سورس کپی نکنید.

1. فونت‌های مجاز Peyda را دقیقاً در `web/src/fonts/peyda/` با این نام‌ها قرار دهید:
   - `PeydaWebFaNum-Regular.woff2`
   - `PeydaWebFaNum-Medium.woff2`
   - `PeydaWebFaNum-Bold.woff2`
   - `PeydaWebFaNum-ExtraBold.woff2`
   - `PeydaWebFaNum-Black.woff2`
2. بکاپ اشیای MinIO را در bucket تنظیم‌شده بازیابی کنید و کلیدهای اشیا را حفظ کنید. manifest به‌تنهایی شامل فایل تصویر نیست.
3. فایل `assets/image-manifest.json` متناظر با همان بکاپ را در ریشهٔ مخزن بازیابی کنید. `key` و `description` باید با محتوا و صفحات فعلی سازگار باشند. این فایل را دستی تغییر ندهید؛ تغییرات بعدی از `POST /api/storage/images` و API مدیریت تصاویر انجام می‌شوند.
4. بکاپ MongoDB را جداگانه بازیابی کنید تا کاربران و آخرین نسخهٔ مقالات حفظ شوند. برای محیط نمونهٔ تازه، پس از آماده‌شدن API، از ریشه `npm run seed:articles` را اجرا کنید. این seed جایگزین بکاپ کاربران یا ویرایش‌های جدید مقالات نیست.
5. اطلاعات ورود و فایل‌های env را از مسیر خصوصی تحویل بگیرید و با محیط مقصد هماهنگ کنید. envهای واقعی را داخل مخزن یا بستهٔ عمومی دارایی‌ها نگذارید.

همهٔ فایل‌های `assets/`، فونت‌ها، اسکرین‌شات‌ها، آرشیوها، داده‌های volume و بکاپ‌ها از گیت کنار گذاشته شده‌اند. کد SVG داخل کامپوننت‌های آیکون بخشی از سورس است؛ فایل‌های مستقل تصویر وارد گیت نمی‌شوند. منابع دارای مجوز و مجوز فونت‌ها را همراه تحویل جداگانه حفظ کنید.

## دستورات

از ریشهٔ مخزن:

```sh
npm run install:all
npm run check:assets
npm run dev
```

برای بررسی یکپارچگی در ترمینال دوم:

```sh
npm run check:integration
```

برای build همهٔ بخش‌ها و اجرای هم‌زمان نسخهٔ آماده:

```sh
npm run build
npm run db:up
npm start
```

برای کار مستقل روی سایت، در حالی که API و MinIO آماده‌اند، `npm run web:dev` را از ریشه اجرا کنید. `npm run typecheck` در پوشهٔ `web/` بررسی TypeScript را انجام می‌دهد.

## انتقال به سرور

کد را همراه ساختار همین monorepo مستقر کنید و دارایی‌های جداگانه را قبل از build بازیابی کنید؛ پنل برای فهرست رسپی‌های CMS به JSON داخل `web/` وابسته است. از فرمان‌های ریشه استفاده کنید تا هر برنامه با working directory صحیح اجرا شود. کاربر اجرای API باید اجازهٔ نوشتن در `assets/` را داشته باشد و سایت باید همان manifest را بخواند. در چند ماشین یا کانتینر، این فایل باید در storage مشترک و پایدار در دسترس باشد.

ریشهٔ file tracing سایت کل مخزن است و manifest در tracing قرار گرفته است. پس از هر آپلود جدید، فایل زندهٔ API باید همچنان با سایتی که در حال اجراست مشترک بماند؛ کپی مستقل زمان build برای این کار کافی نیست. داده‌های MongoDB و MinIO و manifest را با هم بکاپ بگیرید.

این مخزن تنظیمات کامل reverse proxy، TLS یا orchestration برای اجرای production روی چند کانتینر ندارد. برای قرارگرفتن پشت reverse proxy، forwarding سایت باید به `127.0.0.1:3002` دسترسی داشته باشد؛ اسکریپت سایت فعلاً فقط روی loopback گوش می‌دهد. تغییر hostname برای اجرای داخل کانتینر باید در فرمان اجرا انجام شود.
