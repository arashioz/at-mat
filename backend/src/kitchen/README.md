# همراه آشپزی ات‌مت — زیرساخت اولیه

ورودی در `/recipes#recipe-library` است. ارسال درخواست فوراً مسیر `/kitchen/chat/<uuid>` را باز می‌کند. متن اولیه در sessionStorage همان تب نگه‌داری می‌شود تا درخواست ناموفق قابل تکرار باشد؛ متن در URL نیست. سابقهٔ گفتگو و رسپی‌های ذخیره‌شده در MongoDB قرار دارند. `/account` دفتر رسپی و ورود/ثبت‌نام عمومی سایت است و به حساب‌های ERP دسترسی ندارد.

## دو حالت پاسخ

- **catalog (پیش‌فرض):** فقط رسپی‌های منتشرشدهٔ `RecipesService.publicList()` را می‌خواند. انتخاب بر اساس مواد، محدودیت‌های شناخته‌شده، نبود فر و زمان؛ تنظیم مقدار مواد برای ۱ تا ۱۲ نفر؛ فهرست خرید و مراحل پخت از دستور پایه. این حالت مدل زبانی یا تولید آزاد دستور نیست و در رابط «نسخهٔ پایه» معرفی شده است. تفسیر محدودیت‌ها قواعد متنی محدود دارد؛ ایمنی آلرژن تضمین نمی‌شود.
- **model:** آداپتور Responses API برای تولید ساختاریافته بر پایهٔ همین کاتالوگ. در `backend/.env` مقدار `KITCHEN_AI_PROVIDER=openai`، نام مدل سازگار با Structured Outputs در `KITCHEN_AI_MODEL` و کلید در `OPENAI_API_KEY` تنظیم و بک‌اند بازراه‌اندازی شود. هیچ کلیدی در کلاینت یا گیت قرار نمی‌گیرد. شناسهٔ مدل عمداً پیش‌فرض ندارد. اتصال زنده به مدل بدون کلید آزموده نشده است؛ قرارداد و حالت شکست با پاسخ‌های مصنوعی آزموده می‌شوند.

پاسخ مدل باید JSON معتبر با رسپیِ مبتنی بر یک منبع منتشرشده و تعداد نفرات صحیح باشد. لینک‌ها سمت سرور از شناسه‌های مجاز ساخته می‌شوند. HTML اجرا نمی‌شود. خطا، پاسخ ناقص یا نامعتبر به حالت catalog برمی‌گردد و این تغییر برای کاربر توضیح داده می‌شود. زمان دستور و عکس متعلق به دستور پایه‌اند؛ شخصی‌سازی تست آشپزخانه محسوب نمی‌شود. پرسش‌های نگهداری و سلامت از پاسخ‌های محدود و مرورشده استفاده می‌کنند.

به سرویس مدل فقط درخواست، آخرین ۱۲ پیام و دادهٔ عمومی رسپی فرستاده می‌شود؛ نام، ایمیل، رمز و توکن حساب در ورودی مدل نیست. گزینهٔ `store` روی false است. قیمت، موجودی فروشگاه، سفارش و پرداخت در این مرحله وجود ندارد.

## نشست و داده

- نشست عمومی یک توکن تصادفی ۲۵۶ بیتی با هش SHA-256 در پایگاه داده و انقضای ۳۰ روزه دارد. مرورگر فقط کوکی HttpOnly / SameSite=Lax دریافت می‌کند؛ Secure در production فعال است. توکن ادمین پذیرفته نمی‌شود.
- درگاه Next.js در `/api/kitchen/[...path]` فقط مسیرهای تعریف‌شده را عبور می‌دهد، درخواست‌های تغییردهنده را به Origin همان سایت محدود می‌کند، توکن خروجی را حذف می‌کند و پاسخ خصوصی را cache نمی‌کند.
- تمام خواندن/نوشتن گفتگو و رسپی با memberId نشست محدود می‌شود. ثبت‌نام حساب مهمان را ارتقا می‌دهد؛ ورود، فقط گفتگوی مهمانِ همان نشست را منتقل و نشست قبلی را باطل می‌کند. خروج نشست جاری را باطل می‌کند.
- ذخیرهٔ رسپی فقط از پیام پاسخِ متعلق به کاربر انجام می‌شود، نه از JSON ارسالی کلاینت. یک snapshot از دستور نگه داشته می‌شود؛ تغییرات بعدی CMS آن را عوض نمی‌کند. ثبت دوبارهٔ همان پیام نسخهٔ تکراری نمی‌سازد.
- درخواست پیام با UUID پایدار قابل تکرار است. قفل زمان‌دار گفتگو از پاسخ‌های هم‌زمان جلوگیری می‌کند. هر گفتگو حداکثر ۴۰ رفت‌وبرگشت دارد. لیست‌ها در نسخهٔ اول تا ۶۰ گفتگو و ۱۰۰ رسپی را برمی‌گردانند.
- محدودسازی درخواست در MongoDB است. سهم پیام هر مهمان ۳۰ و عضو ۸۰ در ساعت؛ ورود و ثبت‌نام نیز محدود شده‌اند. بک‌اند پیش‌فرض روی loopback است. پیش از انتشار چندکاربره، نرخ‌سنجی IP در reverse proxy قابل اعتماد تنظیم شود؛ هدر IP دلخواه کلاینت در این نسخه اعتماد نمی‌شود.
- ارسال ایمیل، تأیید ایمیل، بازیابی رمز و مدیریت حساب کامل هنوز پیاده‌سازی نشده‌اند. این نسخه زیرساخت محلی اولیه است. کلید واقعی مدل و آزمون کیفیت آن قبل از فعال‌سازی عمومی لازم است.

## بررسی

با سرویس‌های محلی روشن:

```sh
npm --prefix backend run build
node --test backend/scripts/check-kitchen.mjs
npm --prefix web run typecheck
```

تست API حساب‌های موقت با دامنهٔ example.invalid می‌سازد و فقط داده‌های همان حساب‌ها را در finally حذف می‌کند. آزمون‌ها شامل مالکیت، جلوگیری از دسترسی ERP، انتقال مهمان، ماندگاری، تکرار امن پیام و ذخیره، اعتبارسنجی، CSRF و شکست مدل است.

منابع فنی و نگهداری: [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)، [FDA](https://www.fda.gov/consumers/consumer-updates/are-you-storing-food-safely)، [USDA](https://ask.fsis.usda.gov/article/How-do-I-handle-leftovers-safely/).
